## 第二周期（4.26-4.28）— 记忆引擎 v1 核心功能

### 一、核心产出

交付了团队记忆引擎 v1 的核心功能：基于艾宾浩斯遗忘曲线的衰减检测系统、CLI 命令交互（status/search/inject）、事件日志系统（date-partitioned JSON 存储）。完成了第一个可运行的端到端流程：写入事件 → 提取记忆 → 查看状态。

### 二、量化指标

- 代码提交：~8 次（含 1 个 feat commit + 1 个 fix commit）
- 新增代码：~800 行（lib/event-log.ts、lib/decay.ts、lib/ledger.ts、index.ts 等）
- CLI 命令：实现了 6 个 team-memory 子命令
- AI 使用场景：核心算法实现（遗忘曲线公式）、CLI 命令骨架生成、TypeScript 类型定义
- LLM 接口调用：~100 次

### 三、过程复盘与沉淀

**1. 这周主要搞定了哪些具体环节？**

- **事件日志系统**（lib/event-log.ts）：实现了 date-partitioned JSON 存储，支持 append、query、by-date 操作
- **衰减检测系统**（lib/decay.ts）：实现了艾宾浩斯遗忘曲线（9 个间隔：1min→31d），强度计算公式 S = 2^(-elapsed / interval)，5 级强度标签（fresh/strong/fading/weak/critical）
- **记忆账本 v1**（lib/ledger.ts）：实现了基础的 entity.attribute.value 存储，支持 inject、search、status 操作
- **CLI 命令注册**（index.ts）：通过 OpenClaw 插件系统的 tools + commands 接口，注册了 6 个 `openclaw team-memory` 子命令
- AI 分工：Claude 负责生成算法初版（遗忘曲线公式、CLI 命令骨架）、TypeScript 类型定义、存储层接口；我负责调整业务逻辑（category 分类、半衰期选择、CLI 输出格式）

**2. 过程中有没有遇到什么特别不顺的情况？**

- **飞书卡片推送调试失败**：初期尝试在 decay check 时自动推送飞书提醒卡片，但 API 调用一直失败（token 刷新 + card ID 管理问题）。后来决定先 disable 飞书推送，改为 log-only，后续再修复。commit: `fix: disable Feishu card push, keep decay check as log only`
- **TypeScript 类型错误**：OpenClaw 插件的 ToolResult 类型要求严格，initial commit 有多个类型不匹配。通过逐个对照框架类型定义修复。

**3. 有什么下次还能直接复用的东西？**

- 艾宾浩斯衰减计算函数（computeDecayStrength）可以独立复用，不依赖记忆引擎其他模块
- CLI 命令注册模式（commander + OpenClaw plugin commands）是一个标准模板，后续新增命令只需复制骨架

### 四、本周随手记

- 艾宾浩斯遗忘曲线的参数调了 3 版，最终选定了 9 个间隔（1min, 10min, 30min, 1h, 6h, 1d, 3d, 7d, 31d），这个分布既不太密也不太疏
- 发现 `openclaw doctor` 命令很好用，能自动检测配置问题和依赖缺失
- v1 架构是单体 ledger + decay，后续需要考虑拆分

## 第三周期（4.29-5.1）— 架构升级 v2 Memory OS

### 一、核心产出

完成了记忆引擎 v2 架构升级，从单一的"账本+衰减"模型扩展为完整的 Memory OS：五组件架构（Ledger + Graph + Risk + Decay + TMS）。新增了知识图谱自动构建、五维风险评估、TMS 专家画像三大子系统。这是整个项目最重要的架构决策点。

### 二、量化指标

- 代码提交：~12 次（含 1 个重大架构升级 feat commit）
- 新增代码：~1500 行（graph.ts、risk.ts、tms.ts、manager.ts、extractor.ts）
- 核心子系统：从 2 个扩展到 6 个（Ledger, Graph, Risk, Decay, TMS, Extractor）
- CLI 命令：扩展到 10+ 个
- AI 使用场景：架构设计（五组件分层）、图谱算法设计、风险模型权重调参
- LLM 接口调用：~200 次

### 三、过程复盘与沉淀

**1. 这周主要搞定了哪些具体环节？**

- **架构升级**（commit: `feat: upgrade team-memory-engine to v2 Memory OS architecture`）：从 v1 的 ledger+decay 双组件，升级为 v2 的五组件架构。新增了 `lib/manager.ts` 作为统一编排层
- **知识图谱**（lib/graph.ts）：实现了五阶段图谱构建算法（实体节点 → 属性节点 → 版本链连线 → 溯源连线 → 社交连线 → 影响力传播），支持 directed multigraph
- **五维风险模型**（lib/risk.ts）：设计了 TimeDecay/BusinessImpact/LowCoverage/VersionRisk/LowUsage 五个维度的风险评估，双阈值门控（risk > threshold 且 strength < reviewThreshold 才触发）
- **TMS 专家画像**（lib/tms.ts）：基于贡献度分析自动识别团队成员的 expertise areas 和 trust score，数据存储在 memory/tms/profile.json
- **LLM 提取器**（lib/extractor.ts）：实现了从事件日志调用 doubao-seed-2.0-pro 自动提取 entity.attribute.value 三元组，支持闲聊过滤和分类打标
- AI 分工：Claude 负责图谱构建算法、风险模型框架、TMS 分析逻辑的代码生成；我负责调参（风险权重、半衰期、图谱构建顺序）、设计数据流

**2. 过程中有没有遇到什么不顺的情况？**

- **架构复杂度爆炸**：v2 从 2 个组件变成 6 个，初期担心耦合太深。后来设计了 manager.ts 作为唯一入口，各组件只依赖 ledger，不互相依赖，解决了循环依赖问题
- **图谱构建顺序**：五阶段算法的依赖关系容易搞混（必须先有实体节点才能加边），debug 了几次才发现是 phase 顺序不对。最后用严格的 phase-by-phase 顺序解决了
- **openclaw doctor 修复**：环境配置有些问题，通过 `openclaw doctor` 自动检测并修复了一些依赖问题（commit 标记为 "before openclaw doctor fix"）

**3. 有什么下次还能直接复用的东西？**

- 五维风险模型是一个通用的"多维度评分 + 双阈值门控"模式，可以迁移到其他需要风险评估的场景
- Manager 编排模式：manager 是唯一对外暴露的接口，内部组件互不依赖，这个架构模式可以直接复用
- 图谱五阶段构建：phase-by-phase 的构建顺序是固定套路，先节点后边再属性

### 四、本周随手记

- v2 架构升级是最大的单周工作量，但做完了之后系统能力上了一个台阶——从"能存能查"变成了"能感知能预警"
- 五维风险的权重调了几版：最终定为 timeDecay=0.30, businessImpact=0.25, 其他各 0.15。decision 类记忆的遗忘风险确实应该最高
- TMS 的设计灵感来自学术论文（Transactive Memory System），但实现比论文简单很多，就是统计谁贡献了什么

- **CLI inject 飞书卡片推送**：修改了 inject 命令，检测到冲突时自动推送飞书交互卡片到群聊（之前只有 tool 路径推送，CLI 路径不推送）

**2. 过程中有没有遇到什么不顺的情况？**

- **Inject 不检测冲突（最严重的 bug）**：demo 跑 Step 8 时，注入"客户A的交付格式改回 Markdown"竟然创建了新的 entry 而不是检测到冲突。排查了 2 小时，发现根因是 entity/attribute 命名不一致——LLM 存的是 `客户A.交付格式`，CLI inject 用的是 `客户A.格式`。exact match 永远返回空，冲突检测根本没执行。解决方案：在 injectClaim 中，exact match 失败后加 fuzzy lookup fallback，用 semanticSimilarity（Levenshtein 距离）做模糊匹配
- **bc 命令缺失**：demo 脚本 Step 10 用 `bc` 计算平均值，但环境没装。改为 python3 一行搞定：`python3 -c "print(f'{$AVG_MS/1000:.1f}')"`
- **Python heredoc 语法错误**：Step 11 的多个 python3 -c 调用中混入了 bash 变量，导致语法错误。改为单个 `python3 << 'PYEOF' ... PYEOF` 后解决
- **飞书 APP Secret 配置**：demo 环境需要配飞书 app_id/app_secret，初期写在了代码里，后来改为从环境变量读取

**3. 有什么下次还能直接复用的东西？**

- **Fuzzy lookup 模式**：exact match → fuzzy fallback → conflict detection 的三段式查找，是处理命名不一致问题的标准解法
- **竞赛材料模板**：核心代码展示 → 项目亮点 → AI 亮点 → 架构补充 的四段式结构，下次参加其他比赛可以直接套用

### 四、项目介绍 + Demo 录屏演示 + 项目链接

**项目简介**：

企业级记忆引擎 — 面向团队知识断层与遗忘预警的主动式记忆系统。

不是 RAG/知识库（被动检索），而是主动式记忆引擎：不问也推（遗忘预警）、矛盾感知（版本链 + 裁决）、自动画像（TMS 专家识别）。

核心技术：版本链存储（永不覆盖）、艾宾浩斯遗忘曲线（类别感知半衰期）、语义相似度冲突检测（三级分类）、LLM 自动提取（闲聊过滤 + 多模型容灾）、飞书交互卡片（用户点击实时更新）。

接入成本 < 5 分钟：安装 openclaw + 配置 teamId + 绑定飞书 WebSocket，零定制代码。

**项目链接**：https://github.com/Iridium2345/Multi-Agent-Requirement.git

**技术栈**：TypeScript / Node.js / OpenClaw 插件系统 / 飞书 WebSocket / doubao-seed-2.0-pro
