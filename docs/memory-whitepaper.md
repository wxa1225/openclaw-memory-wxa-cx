  ——从"信息存储"到"团队认知维持"                                                                                                                                                         
                                                                                                                                                                                         
  ---             
  摘要                                                                                                                                                                                   
                                                                                                                                                                                         
  ▎ 在日常办公场景中，大模型往往是"失忆"的。哪怕它绝顶聪明，每次对话也总是"从零开始"。团队同样如此——群聊里做出的决策、客户确认的偏好、关键事项的变更，几周后便从全员记忆中消失。
  ▎                                                                                                                                                                                      
  ▎ 本文提出一种面向企业协作场景的团队认知系统，将团队共享记忆建模为一个动态演化的时序知识系统，并引入遗忘风险建模与版本化语义约束，实现从"信息存储"到"认知维持"的转变。系统在飞书群聊与C
  ▎ LI终端间无缝流转，基于OpenClaw agent框架实现记忆的自动提取、概率化存储、风险预警与冲突消解。

  一、重新定义"记忆"——方向D的场景切入
                                                                                                                                                                                         
  1.1 问题：团队为什么会"遗忘"？
                                                                                                                                                                                         
  团队项目中，以下信息一旦被提及，若没有有效的记忆机制，几周后就会被全员遗忘并导致错误：                                                                                                 
                                                                                                                                                                                         
  - 客户偏好变更："客户A以后要PDF交付，不要再发Markdown了"                                                                                                                               
  - 关键参数更新："API密钥已轮换，旧密钥本周五失效"
  - 决策回溯："上周五确认了截止日期是5号，不是15号"                                                                                                                                      
  - 流程调整："周报以后统一发给B，不要再抄送A了"                                                                                                                                         
                                                                                                                                                                                         
  这些信息的共同特征：                                                                                                                                                                   
  1. 隐含在对话中（非正式文档）                                                                                                                                                          
  2. 时序敏感（有有效期，会被后续更新覆盖）                                                                                                                                              
  3. 团队共享（不是个人记忆，需要多角色同步）
  4. 遗忘有代价（返工、错误交付、客户投诉）                                                                                                                                              
                                                                                                                                                                                         
  1.2 我们对"记忆"的定义                                                                                                                                                                 
                                                                                                                                                                                         
  ▎ 企业环境中有价值的记忆，不是聊天记录，不是文档存档，而是团队在特定时间点达成共识、对未来行为具有约束力、且会随时间衰减的时序性知识。                                                 
                                                                                                                                                                                         
  按此定义，我们将记忆分为三类：                                                                                                                                                         
                  
  ┌────────┬───────────────────┬──────────┬──────────────────┐                                                                                                                           
  │  类型  │       示例        │ 衰减速度 │     遗忘代价     │
  ├────────┼───────────────────┼──────────┼──────────────────┤                                                                                                                           
  │ 决策型 │ "用方案B不用A"    │ 慢       │ 高（重复争论）   │
  ├────────┼───────────────────┼──────────┼──────────────────┤                                                                                                                           
  │ 偏好型 │ "客户要PDF交付"   │ 中       │ 高（错误交付）   │                                                                                                                           
  ├────────┼───────────────────┼──────────┼──────────────────┤                                                                                                                           
  │ 事实型 │ "API key周五失效" │ 快       │ 极高（服务中断） │                                                                                                                           
  └────────┴───────────────────┴──────────┴──────────────────┘

  二、理论统一：Team Memory = Temporal + Probabilistic + Social
                                                                                                                                                                                         
  我们不是简单拼接"遗忘曲线+JSON存储+群聊机器人"，而是将三个理论融合为一个统一的数学框架：
                                                                                                                                                                                         
  2.1 三个理论基座                                                                                                                                                                       
                                                                                                                                                                                         
  ① 交互记忆系统（Transactive Memory System, TMS）                                                                                                                                       
                  
  团队不是"记住内容"，而是记住：谁知道什么 + 是否可信 + 什么时候需要用。这解释了为什么同一个信息，在张三嘴里是"常识"，在李四那里是"新闻"——记忆的有效性是社交上下文相关的。               
                  
  ② 间隔重复与遗忘（Spaced Repetition → 概率化遗忘）                                                                                                                                     
                  
  经典Ebbinghaus遗忘曲线描述的是个体记忆衰减。我们将其升级为：团队对某条记忆的"正确使用概率"不是一个0/1开关，而是一个随时间变化的概率分布。                                              
                  
  ③ 时序知识图谱（Temporal Knowledge Graph）                                                                                                                                             
                  
  知识不是静态条目，而是时间演化的事实。同一条记忆在不同时间点可能有不同版本，每个版本都有自己的有效区间和置信度。                                                                       
                  
  2.2 统一模型：时序概率记忆实体                                                                                                                                                         
                  
  团队记忆 m 被定义为一个六元组：                                                                                                                                                        
                  
  m = (content, context, owner, validity_interval, P_recall(t), dependency_graph)                                                                                                        
                                                                                                                                                                                         
  ┌───────────────────┬─────────────────────────────────────┬────────────────────────────────────────────────────────────────────┐                                                       
  │       字段        │                含义                 │                                示例                                │                                                       
  ├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤                                                       
  │ content           │ 记忆内容（结构化）                  │ {entity: "客户A", attribute: "交付格式", value: "PDF"}             │
  ├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤                                                       
  │ context           │ 来源上下文                          │ {source: "群聊", msg_id: "msg-123", participants: ["张三","李四"]} │                                                       
  ├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤                                                       
  │ owner             │ 记忆归属人/角色                     │ "张三"（注入者）                                                   │                                                       
  ├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤                                                       
  │ validity_interval │ 有效时间区间                        │ [2026-04-20, null]（null表示尚未失效）                             │
  ├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤                                                       
  │ P_recall(t)       │ 团队在时间t正确 recall 该记忆的概率 │ 2^(-Δt / h_m)                                                      │
  ├───────────────────┼─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┤                                                       
  │ dependency_graph  │ 与其他记忆/任务的依赖关系           │ ["mem-002", "task-T102"]                                           │
  └───────────────────┴─────────────────────────────────────┴────────────────────────────────────────────────────────────────────┘                                                       
                  
  核心公式：团队遗忘风险模型                                                                                                                                                             
                  
  P_recall(m, t) = 2^(-Δt / h_m)           # 基础遗忘概率（Ebbinghaus推广）                                                                                                              
  TimeDecay(m, t) = 1 - P_recall(m, t)     # 时间衰减因子                                                                                                                                
                                                                                                                                                                                         
  Risk(m, t) = w₁ × TimeDecay                                                                                                                                                            
             + w₂ × BusinessImpact(m)                                                                                                                                                    
             + w₃ × LowCoverage(m)                                                                                                                                                       
             + w₄ × VersionRisk(m)                                                                                                                                                       
             + w₅ × LowUsage(m)                                                                                                                                                          
                                                                                                                                                                                         
  权重分配：                                                                                                                                                                             
                                                                                                                                                                                         
  ┌────────────────┬──────┬───────────────────────────────────────┐                                                                                                                      
  │      因子      │ 权重 │                 含义                  │
  ├────────────────┼──────┼───────────────────────────────────────┤                                                                                                                      
  │ TimeDecay      │ 0.35 │ 时间衰减：距上次确认的天数            │
  ├────────────────┼──────┼───────────────────────────────────────┤                                                                                                                      
  │ BusinessImpact │ 0.25 │ 业务影响：该记忆关联的任务/客户重要性 │                                                                                                                      
  ├────────────────┼──────┼───────────────────────────────────────┤                                                                                                                      
  │ LowCoverage    │ 0.20 │ 覆盖率：团队中有多少人知晓此记忆      │                                                                                                                      
  ├────────────────┼──────┼───────────────────────────────────────┤                                                                                                                      
  │ VersionRisk    │ 0.10 │ 版本风险：是否存在冲突版本            │
  ├────────────────┼──────┼───────────────────────────────────────┤                                                                                                                      
  │ LowUsage       │ 0.10 │ 使用频率：近期被引用的次数            │
  └────────────────┴──────┴───────────────────────────────────────┘

  3.2 核心突破：Memory Ledger（版本账本）                                                                                                                                                
                  
  每条记忆不是"被覆盖"，而是进入一个演化链：                                                                                                                                             
                  
  mem-001 v1 ("客户A要Markdown") ──┐                                                                                                                                                     
                                    ├── mem-001 v2 ("客户A要PDF")                                                                                                                        
  mem-002 v1 ("PDF替代Markdown")───┘                                                                                                                                                     
                                    └── superseded: mem-001 v1                                                                                                                           
                                                                                                                                                                                         
  Ledger 结构：                                                                                                                                                                          
                                                                                                                                                                                         
  {                                                                                                                                                                                      
    "id": "mem-001",
    "entity": "客户A",                                                                                                                                                                   
    "attribute": "交付格式",                                                                                                                                                             
    "claims": [                                                                                                                                                                          
      {                                                                                                                                                                                  
        "version": 1,                                                                                                                                                                    
        "value": "Markdown",                                                                                                                                                             
        "valid_from": "2026-04-10T10:00:00Z",                                                                                                                                            
        "valid_to": "2026-04-26T14:30:00Z",                                                                                                                                              
        "confidence": 0.85,                                                                                                                                                              
        "source": "msg-456",                                                                                                                                                             
        "injected_by": "张三"                                                                                                                                                            
      },                                                                                                                                                                                 
      {                                                                                                                                                                                  
        "version": 2,                                                                                                                                                                    
        "value": "PDF",                                                                                                                                                                  
        "valid_from": "2026-04-26T14:30:00Z",                                                                                                                                            
        "valid_to": null,                                                                                                                                                                
        "confidence": 0.92,                                                                                                                                                              
        "source": "msg-789",                                                                                                                                                             
        "injected_by": "李四",                                                                                                                                                           
        "confirmed_by": ["王五"]                                                                                                                                                         
      }                                                                                                                                                                                  
    ],                                                                                                                                                                                   
    "current_version": 2,                                                                                                                                                                
    "dependency_graph": ["mem-002", "task-T102"],                                                                                                                                        
    "recall_half_life": 14  # 天，该记忆的遗忘半衰期                                                                                                                                     
  }                                                                                                                                                                                      
                                                                                                                                                                                         
  3.3 Memory Graph（团队认知图谱）                                                                                                                                                       
                  
  Memory Graph不是"多存几个字段"，而是把记忆变成可推理的知识网络。                                                                                                                       
                  
  节点类型（Node）：                                                                                                                                                                     
  - 实体（客户A、项目X、张三）
  - 记忆版本（mem-001-v1、mem-001-v2）                                                                                                                                                   
  - 事件（4月20日群聊消息、交付任务T-102）
  - 属性值（Markdown、PDF、4月20日）                                                                                                                                                     
                                                                                                                                                                                         
  边类型（Edge）：                                                                                                                                                                       
                                                                                                                                                                                         
  ┌────────────────┬─────────────────────────┬───────────┐                                                                                                                               
  │    关系类型    │          示例           │   方向    │                                                                                                                               
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ has_preference │ 客户A → 交付格式        │ 实体→属性 │
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ current_value  │ 交付格式 → PDF          │ 属性→值   │                                                                                                                               
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ supersedes     │ mem-001-v2 → mem-001-v1 │ 版本→版本 │                                                                                                                               
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ derived_from   │ mem-001-v2 → msg-789    │ 记忆→事件 │
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ confirmed_by   │ mem-001-v2 → 王五       │ 记忆→人   │
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ affects        │ mem-001-v2 → 任务T-102  │ 记忆→任务 │
  ├────────────────┼─────────────────────────┼───────────┤                                                                                                                               
  │ injected_by    │ mem-001-v1 → 张三       │ 记忆→人   │
  └────────────────┴─────────────────────────┴───────────┘                                                                                                                               
                  
  图谱推理示例：                                                                                                                                                                         
                  
  客户A                                                                                                                                                                                  
   ├── has_preference → 交付格式                                                                                                                                                         
   │                    ├── current_value → PDF (v2, 有效)                                                                                                                               
   │                    └── old_value → Markdown (v1, 已覆盖)                                                                                                                            
   ├── related_memory → mem-001-v2                                                                                                                                                       
   │                    ├── supersedes → mem-001-v1                                                                                                                                      
   │                    ├── derived_from → msg-789                                                                                                                                       
   │                    ├── confirmed_by → 王五                                                                                                                                          
   │                    └── valid_from → 2026-04-26                                                                                                                                      
   └── affected_task → 本周交付任务                                                                                                                                                      
                                                                                                                                                                                         
  3.4 冲突处理：规则 + 推理                                                                                                                                                              
                                                                                                                                                                                         
  冲突检测条件： 同一 entity + 同一 attribute + 时间重叠 + value 不同                                                                                                                    
                  
  三级处理策略：                                                                                                                                                                         
                  
  ┌──────────┬─────────────────────────────────────────┬────────────────────────────────────┐                                                                                            
  │   场景   │                判定条件                 │              处理方式              │
  ├──────────┼─────────────────────────────────────────┼────────────────────────────────────┤                                                                                            
  │ 自动覆盖 │ 新记忆置信度 > 旧记忆 + 0.2，且有确认者 │ 自动标记旧版本 superseded          │
  ├──────────┼─────────────────────────────────────────┼────────────────────────────────────┤                                                                                            
  │ 标记冲突 │ 置信度接近（差值 < 0.15）               │ 标记 conflicting，生成冲突卡片推送 │                                                                                            
  ├──────────┼─────────────────────────────────────────┼────────────────────────────────────┤                                                                                            
  │ 请求人工 │ 双方置信度低（均 < 0.6）                │ 在群聊中 @相关人员 请求确认        │                                                                                            
  └──────────┴─────────────────────────────────────────┴────────────────────────────────────┘

  五、核心创新点（Contributions）                                                                                                                                                        
                                                                                                                                                                                         
  Contribution 1：团队遗忘风险模型
                                                                                                                                                                                         
  首次将 Ebbinghaus 遗忘曲线推广到团队多角色场景，引入业务影响、覆盖率、版本风险等多因子，形成可量化的遗忘风险评分。系统不等待记忆"丢失"才补救，而是通过风险预测提前干预。               
                                                                                                                                                                                         
  Contribution 2：解释型协作提醒                                                                                                                                                         
                  
  区别于传统"到期提醒"，系统提醒的是风险而非事件。每条预警附带：                                                                                                                         
  - 当前版本及来源
  - 风险因子分解                                                                                                                                                                         
  - 可操作建议（确认/更新/忽略）
                                                                                                                                                                                         
  这显著降低了"过度提醒"的问题（见评测5.4）。                                                                                                                                            
                                                                                                                                                                                         
  Contribution 3：记忆是"活系统"                                                                                                                                                         
                                                                                                                                                                                         
  ┌──────────┬────────────┬─────────────────────┐                                                                                                                                        
  │   维度   │ 传统知识库 │       本系统        │
  ├──────────┼────────────┼─────────────────────┤                                                                                                                                        
  │ 更新方式 │ 手动编辑   │ 对话自动提取        │
  ├──────────┼────────────┼─────────────────────┤                                                                                                                                        
  │ 版本管理 │ 覆盖旧版   │ 版本链 + 冲突检测   │                                                                                                                                        
  ├──────────┼────────────┼─────────────────────┤                                                                                                                                        
  │ 失效机制 │ 无         │ 遗忘概率 + 人工确认 │                                                                                                                                        
  ├──────────┼────────────┼─────────────────────┤                                                                                                                                        
  │ 主动性   │ 被动查询   │ 风险主动推送        │
  ├──────────┼────────────┼─────────────────────┤                                                                                                                                        
  │ 团队维度 │ 个人存储   │ 社交上下文 + 覆盖率 │
  └──────────┴────────────┴─────────────────────┘

  六、评测：自证报告（Benchmark Report）
                                                                                                                                                                                         
  ▎ 比赛要求至少包含抗干扰测试和矛盾更新测试，我们额外设计了三项评测形成完整闭环。
                                                                                                                                                                                         
  6.1 抗干扰测试（必做）                                                                                                                                                                 
                                                                                                                                                                                         
  目标：在大量无关对话/操作后，系统能否精准捞取关键记忆。                                                                                                                                
                  
  方法：                                                                                                                                                                                 
  - 注入5条关键记忆（决策/偏好/事实各类型）
  - 插入1000条无关群聊消息（覆盖闲聊、技术讨论、日程通知等）                                                                                                                             
  - 7天后查询5条关键记忆                                    
                                                                                                                                                                                         
  指标：                                                                                                                                                                                 
                                                                                                                                                                                         
  ┌─────────────────────┬───────┬──────────────────────────┐                                                                                                                             
  │        指标         │ 目标  │         测量方式         │                                                                                                                             
  ├─────────────────────┼───────┼──────────────────────────┤                                                                                                                             
  │ 召回率（Recall）    │ ≥ 90% │ 正确检索到的关键记忆 / 5 │
  ├─────────────────────┼───────┼──────────────────────────┤                                                                                                                             
  │ 精确率（Precision） │ ≥ 85% │ 正确检索 / 总检索结果    │                                                                                                                             
  ├─────────────────────┼───────┼──────────────────────────┤                                                                                                                             
  │ 检索延迟            │ < 2秒 │ 从查询到返回的时间       │                                                                                                                             
  └─────────────────────┴───────┴──────────────────────────┘                                                                                                                             
                  
  6.2 矛盾更新测试（必做）                                                                                                                                                               
                  
  目标：证明系统能理解时序，正确覆写冲突记忆。                                                                                                                                           
                  
  方法：                                                                                                                                                                                 
  1. T0：注入 "以后周报发给A" → 创建 mem-010 v1
  2. T1：注入 "不对，以后周报发给B" → 应创建 mem-010 v2，v1 标记 superseded                                                                                                              
  3. T2：查询"周报发给谁" → 应返回B，且附带v1的历史记录                    
                                                                                                                                                                                         
  指标：                                                                                                                                                                                 
                                                                                                                                                                                         
  ┌────────────┬───────┬─────────────────────────────────────┐                                                                                                                           
  │    指标    │ 目标  │              测量方式               │                                                                                                                           
  ├────────────┼───────┼─────────────────────────────────────┤                                                                                                                           
  │ 版本正确性 │ 100%  │ 返回最新版本的正确值                │
  ├────────────┼───────┼─────────────────────────────────────┤                                                                                                                           
  │ 历史可追溯 │ 100%  │ 旧版本仍可查询（标记为 superseded） │                                                                                                                           
  ├────────────┼───────┼─────────────────────────────────────┤                                                                                                                           
  │ 冲突识别率 │ ≥ 95% │ 系统正确识别冲突的比率              │                                                                                                                           
  └────────────┴───────┴─────────────────────────────────────┘                                                                                                                           
                  
  6.3 记忆保持率（Memory Retention）                                                                                                                                                     
                  
  目标：验证遗忘模型的准确性。                                                                                                                                                           
                  
  方法：                                                                                                                                                                                 
  - 注入20条不同类型的记忆
  - 在 1天/3天/7天/14天/30天 时间点查询                                                                                                                                                  
  - 对比模型预测的 P_recall 与实际 recall 结果
                                                                                                                                                                                         
  指标：                                                                                                                                                                                 
                                                                                                                                                                                         
  ┌────────────┬─────────────────────────────────┐                                                                                                                                       
  │    指标    │              目标               │                                                                                                                                       
  ├────────────┼─────────────────────────────────┤                                                                                                                                       
  │ 7天保持率  │ ≥ 80%                           │
  ├────────────┼─────────────────────────────────┤                                                                                                                                       
  │ 30天保持率 │ ≥ 50%（关键记忆应触发复习提醒） │                                                                                                                                       
  ├────────────┼─────────────────────────────────┤                                                                                                                                       
  │ 模型拟合度 │ R² ≥ 0.85（预测 vs 实际）       │                                                                                                                                       
  └────────────┴─────────────────────────────────┘                                                                                                                                       
                  
  6.4 过度提醒率（Over-Reminder Rate）                                                                                                                                                   
                  
  目标：衡量预警系统的精度——提醒中有多少是"不必要的"。                                                                                                                                   
                  
  方法：                                                                                                                                                                                 
  - 运行系统14天，记录所有推送的风险预警
  - 人工标注每条预警的"必要性"（是否真的需要提醒）                                                                                                                                       
                                                  
  指标：                                                                                                                                                                                 
                                                                                                                                                                                         
  ┌────────────┬─────────────────────────────────────────────────┐                                                                                                                       
  │    指标    │                      目标                       │                                                                                                                       
  ├────────────┼─────────────────────────────────────────────────┤                                                                                                                       
  │ 过度提醒率 │ < 15%                                           │
  ├────────────┼─────────────────────────────────────────────────┤                                                                                                                       
  │ 用户操作率 │ > 60%（用户对预警进行确认/更新/忽略操作的比例） │                                                                                                                       
  └────────────┴─────────────────────────────────────────────────┘                                                                                                                       
                                                                                                                                                                                         
  6.5 效能指标验证                                                                                                                                                                       
                  
  目标：量化展示系统带来的实际效率提升。                                                                                                                                                 
                  
  场景：新成员加入项目后了解历史决策                                                                                                                                                     
                  
  ┌───────────────────────────┬──────────────────────┬──────────────────┬──────┐                                                                                                         
  │           场景            │        使用前        │      使用后      │ 提效 │
  ├───────────────────────────┼──────────────────────┼──────────────────┼──────┤                                                                                                         
  │ 查找3个月前的交付格式决策 │ 翻聊天记录 ~15分钟   │ 查询记忆 ~5秒    │ 99%  │
  ├───────────────────────────┼──────────────────────┼──────────────────┼──────┤                                                                                                         
  │ 确认API key是否已更新     │ 询问团队成员 ~10分钟 │ 查询记忆 ~5秒    │ 99%  │                                                                                                         
  ├───────────────────────────┼──────────────────────┼──────────────────┼──────┤                                                                                                         
  │ 避免重复讨论已决策事项    │ 重复讨论 ~30分钟/次  │ 推送历史决策卡片 │ 100% │                                                                                                         
  └───────────────────────────┴──────────────────────┴──────────────────┴──────┘

  七、总结        
                                                                                                                                                                                         
  本系统将"记忆"从被动的信息存储升级为主动的团队认知维持基础设施。核心贡献在于：
                                                                                                                                                                                         
  1. 理论层面：将 TMS、遗忘曲线、时序知识图谱统一为"时序概率记忆实体"模型                                                                                                                
  2. 架构层面：四层 Memory OS（Event Log → Extraction → Ledger → Graph），支持版本追溯和冲突消解                                                                                         
  3. 实践层面：在飞书 + OpenClaw 生态中实现端到端闭环，记忆从群聊对话中自动提取，通过风险预警主动干预                                                                                    
  4. 评测层面：五项评测指标覆盖召回、精确、保持、过度提醒和效能，形成完整的自证闭环                                                                                                      
                                                                                                                                                                                         
  ▎ 记忆不是文档，而是活系统——它会生长、会被覆盖、会被遗忘，但也可以被唤醒。
