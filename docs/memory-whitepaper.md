# 企业级长程协作 Memory 系统 —— 定义与架构白皮书

> 方向 D：团队知识断层与遗忘预警

---

## 1. 记忆定义

### 什么是有价值的"团队记忆"？

在企业协作环境中，**记忆不是聊天记录本身，而是从协作流中沉淀下来的、对后续决策/执行有指导意义的结构化知识**。我们将团队记忆分为四类：

| 类别 | 示例 | 遗忘风险 |
|------|------|----------|
| **决策** | "采用方案B做多租户隔离" | 高 — 几周后无人记得选择原因 |
| **事实** | "生产 API 密钥已更新为 v2" | 极高 — 错误使用旧密钥导致事故 |
| **流程** | "每周五 3 点发周报给张明" | 中 — 新员工不知道，老员工遗忘 |
| **经验** | "QPS > 500 时数据库连接池需要扩容" | 高 — 故障排查时重复踩坑 |

### 记忆的生命周期

```
注入 → 存储 → 检索 → 衰减 → 复习提醒 → 确认/更新 → 新一轮衰减
                                    ↓
                               遗忘（未复习）
```

### 2.2 核心模块

| 模块 | 文件 | 职责 |
|------|------|------|
| **Plugin 入口** | `index.ts` | 注册工具/CLI/后台服务，插件生命周期管理 |
| **记忆管理器** | `lib/manager.ts` | CRUD 编排、双存储（本地 + Mem0）、版本链维护 |
| **遗忘曲线** | `lib/decay.ts` | Ebbinghaus 衰减计算、复习阈值判断、飞书卡片格式化 |
| **本地存储** | `lib/storage/local.ts` | JSON 文件持久化 + 全文检索 |
| **类型定义** | `lib/storage/types.ts` | 跨模块共享接口 |

### 2.3 遗忘曲线模型

采用 **Ebbinghaus 间隔重复** 模型，9 级复习间隔：

```
1min → 10min → 1h → 9h → 1d → 2d → 6d → 15d → 31d
```

记忆强度计算公式：`S = 2^(-elapsed / current_interval)`

- 注入/复习后：S = 100%，进入下一个更长间隔
- 在间隔边界：S = 50%
- 超过阈值（默认 40%）：触发复习提醒
- 连续通过复习：间隔延长，记忆更持久

强度标签：
| 标签 | 强度范围 | 颜色 |
|------|----------|------|
| FRESH | ≥ 80% | 蓝色 |
| STRONG | 50–79% | 蓝色 |
| FADING | 30–49% | 黄色 |
| WEAK | 10–29% | 橙色 |
| CRITICAL | < 10% | 红色 |

## 3. 存储策略

### 双存储架构

```
                    ┌─────────────┐
                    │  Manager    │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
       ┌──────────┐  ┌──────────┐  ┌──────────┐
       │ 本地 JSON │  │ Mem0 API │  │ (未来)   │
       │ (主存储)  │  │ (语义搜索)│  │ 向量数据库│
       └──────────┘  └──────────┘  └──────────┘
```

- **本地 JSON**：写入原子操作（.tmp → rename），保证数据一致性，无需外部依赖
- **Mem0**：当 API key 可用时作为语义搜索加速器，不可用时完全不影响系统运行
- 本地存储是 **单一事实来源**，Mem0 仅用于增强搜索能力

## 4. 版本管理

每次更新记忆时：
1. 版本号 +1
2. 旧内容保留在 `versionHistory` 中
3. 衰减曲线重置（视为"新复习"）
4. 记录更新者身份

```json
{
  "version": 2,
  "memory": "以后周报发给 Bob",
  "versionHistory": [
    { "version": 1, "text": "以后周报发给 Alice", "updatedBy": "user-A" },
    { "version": 2, "text": "以后周报发给 Bob",   "updatedBy": "user-B" }
  ]
}
```

## 5. 交互方式

### CLI 终端
```bash
openclaw team-memory inject "记忆内容" --category api --tags "key,prod"
openclaw team-memory status                    # 查看所有记忆及衰减状态
openclaw team-memory search "关键词"            # 全文检索
openclaw team-memory review <id>               # 标记已复习
openclaw team-memory list --json               # JSON 格式输出
```

### 飞书工具（Agent 调用）
- `team_memory_inject` — 注入新记忆
- `team_memory_update` — 更新已有记忆（自动版本管理）
- `team_memory_status` — 查看记忆状态
- `team_memory_review` — 标记复习

## 6. 企业价值

| 痛点 | 传统方式 | 本系统方案 |
|------|----------|-----------|
| 决策被遗忘 | 翻聊天记录 | 主动复习提醒 |
| 信息版本混乱 | 多人说不同版本 | 版本链追溯 |
| 新人入职成本高 | 口头交接/翻文档 | 记忆系统直达 |
| 关键信息衰减 | 无感知丢失 | 强度可视化+预警 |
