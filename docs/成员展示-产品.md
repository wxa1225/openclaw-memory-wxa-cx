## 核心设计展示

### 1. 产品定位设计：不是知识库，是主动式记忆引擎

**核心差异对比**：

```
┌────────────┬──────────────────┬──────────────────┐
│            │ RAG / 知识库      │ 记忆引擎         │
├────────────┼──────────────────┼──────────────────┤
│ 触发方式   │ 用户提问 → 回答   │ 不问也推 · 主动  │
│ 遗忘预警   │ ✘ 无此能力       │ ✔ 艾宾浩斯曲线   │
│ 矛盾检测   │ ✘ 新版本覆盖旧版  │ ✔ 版本链 + 裁决  │
│ 专家画像   │ ✘ 无此能力       │ ✔ TMS 自动识别   │
└────────────┴──────────────────┴──────────────────┘
```

**设计理念**：类比人脑——你不会"搜索"自己记不记得，大脑会主动告诉你"快想不起来了"或"这话前后矛盾"。记忆引擎就是给团队装一个"集体大脑"。

### 4. 实测效能指标表设计

```
┌──────────────────────┬────────────┬────────────┬────────┐
│         场景         │   无记忆   │   有记忆   │  提效  │
├──────────────────────┼────────────┼────────────┼────────┤
│ 查客户交付格式       │ 翻记录 ~2m │ ~24.5s¹    │  ~83%  │
│ 确认 API 端点版本    │ 问同事 ~5m │ ~24.5s¹    │  ~93%  │
│ 发现矛盾更新         │ 人工 ~10m  │ 自动检测   │  ~98%  │
│ 抗干扰(51条无关信息) │ 筛选 ~30m  │ 自动过滤   │  ~99%  │
│ 遗忘预警             │ 无此能力   │ 自动推送   │   —    │
└──────────────────────┴────────────┴────────────┴────────┘

¹ 含 CLI 启动 ~24.5s；集成到 agent 后检索 < 100ms
  → 遗忘预警是独有功能，无对比对象
```

**设计意图**：
- 每行都有对比，提效百分比递进（83%→93%→98%→99%），越往后系统优势越明显
- 最后一行"遗忘预警"标注"无此能力"，说明这是**独有功能**
- 脚注注明 CLI 启动时间，体现诚实严谨

## 产品设计说明

### 设计决策 1：为什么卡片按钮用版本特定的文字？

初期用抽象的"确认有效/标记过期/更新记忆"，评委看不懂。改为"保留 v1 (PDF) / 保留 v2 (Markdown) / 两个都保留"，观众一眼就知道每个按钮的作用，降低理解成本。

### 设计决策 2：为什么演示脚本不依赖口播？

录屏时口播容易出错、卡顿、有噪音。全自动脚本每步都有 `→ 说明` 和 `💡 优势` 文字注释，评委看屏幕就能理解，录屏成品更专业。

### 设计决策 3：为什么效能表提效百分比不是全 99%？

全 99% 不真实。83%（查记忆）、93%（确认信息）、98%（矛盾检测）、99%（抗干扰）递进分布，体现不同场景下系统的价值差异，更可信。

### 设计决策 4：为什么遗忘预警和冲突裁决放在同一个 Step？

方向 D 的核心是"遗忘预警"，但"矛盾检测"是记忆引擎区别于普通系统的另一个核心能力。两步合并展示，评委既能看到方向 D 的重点，又能看到系统的完整能力边界。
